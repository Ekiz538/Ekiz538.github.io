Project 01 · Live system

Outpost DMS

Multi-depot distribution management system for LAPOK Ventures — stock taking, dispatch, cash handover and leadership reporting, live at dms.afriboards.com.

Open the live system Source on GitHub

PHP APIs · MySQL · vanilla JavaScript · Truehost shared hosting · deployed under the company's domain

The problem

LAPOK Ventures distributes products across multiple depots. Stock movements, sales and cash handovers were tracked manually, which made reconciliation slow and gave leadership no reliable view of what each depot held, sold or handed over on any day.

What the system does

Outpost DMS is a multi-depot platform covering stock taking and dispatch, sales, cash handover, and leadership reporting — with distinct, guarded workflows for cadets (field delivery), accountants (RDC review), managers and admins, including a PDF report chain for leadership.

Engineering decisions

  • Server-side role ownership. Permissions are enforced at the API layer: a wrong-role page bounces home with a toast. Hiding menu items is never the security boundary.
  • Dispatch resolved server-side from approved assignments. Admin maintains the recurring Monday–Saturday cadet, vehicle and route board; managers dispatch stock but route and cadet data are re-resolved by the server from today's approved assignment. Missing or incomplete assignments — and Sundays — block dispatch entirely, so stock cannot move without an authorised plan behind it.
  • Audited financial edits. Account changes flow through an RDC review and manager-approval workflow instead of direct edits, creating an audit trail for every correction.
  • One shared navigation model. Every account uses the same off-canvas left menu — full-width dashboard until pinned, closed by selecting a page, clicking outside, or pressing Escape — keeping the UI consistent across role experiences without per-role layouts.

Data model & deployment

The MySQL backend spans a 14-table relational schema with session-based authentication. Deployment runs on Truehost shared hosting with the production database under the company's own domain. The build ships with no seeded sample transactions — operational accounts are created and secured per deployment, and every code push is logged in a team changelog with date, author and summary.

Stakeholders & outcomes

Presented to Coca-Cola executives and the client's board during my internship. Depot staff use the system in day-to-day operations: cadets log deliveries against their assigned routes, accountants run RDC reviews, and leadership reads generated PDF reports rather than chasing spreadsheets.

Honest constraints

Integration with external systems (CCBA reporting feeds, EFRIS invoicing, fleet GPS) is manual or deferred in this build. Knowing and stating the boundary of a system is part of maintaining it responsibly.
